## Scope

10 core tables: `users`, `family_profiles`, `trip_briefs`, `hotels`, `raw_reviews`, `hotel_intelligence`, `sessions`, `shortlists`, `pipeline_runs`, `pipeline_run_hotels`. Plus `curation_hotels` staging (not in the core 10), `raw_review_payloads` (migration 0009 — original untouched Apify actor items, for re-mapping without a re-scrape), the RouteStack id-cache tables `routestack_destinations` + `routestack_hotels` (migration 0011 — cache the stable RouteStack destination/hotel ids for the booking flow), and `apify_runs` (migration 0012 — the Apify run ledger: one row per actor run, so an expensive run is recoverable/re-pullable/refreshable; see 12h). Plus `preview_seeds` (migration 0014 — per-destination seed-once latch for on-the-fly preview seeding from chat; see 12i-C), `raw_routestack_payloads` (migration 0015 — opt-in redacted debug log of RouteStack API calls; see 10c), `booking_orders` + `webhook_events` (migration 0016 — booking-order lifecycle tracking + the inbound-webhook audit log; see 10d), and `recommendation_jobs` (migration 0018 — the async-assembly job ledger: one row per recommendation assembly so the slow LLM call runs off the `/api/chat` 60s budget; **owner-read** RLS so the client poll reads its own job; see 03c). *(scope list synced 2026-07-03, post-review sweep)*

Authoritative details (columns, types, indexes, SQL for pipeline + curation tables) are in `docs/data-model.md` and must match Notion 07 exactly.

## Key invariants

- `hotels.star_rating` ∈ {3, 4, 5}.
- `hotels.price_tier` ∈ {mid-range, luxury, ultra-luxury}.
- `hotels.source` ∈ {curated, preview} (migration `0013`, default `curated`). `curated` = Apify-curated + review-intelligence-backed (showcase tier); `preview` = Claude-proposed + RouteStack-verified, **no `hotel_intelligence` row**, surfaced with an honest "preview" label. See **12i · Preview Destinations**.
- `hotels.area` is nullable (card shows destination only when null).
- `raw_reviews` is permanently accumulated; deduped via `UNIQUE (hotel_id, source, reviewer_name, review_date, anon_text_hash) NULLS NOT DISTINCT` (migration `0020` — `anon_text_hash` is a stored generated column, `md5(review_text)` only when BOTH reviewer_name and review_date are null, else `''`, so undated/anonymous reviews dedup across runs without collapsing distinct ones); carries `pipeline_run_id`. *(updated 2026-07-03, post-review sweep)*
- `hotel_intelligence.low_confidence` defaults `false`; `true` suppresses the hotel from recommendations. `hotel_intelligence.confidence` (`high` | `medium` | `low`, nullable — migration `0021`) persists the synthesis gate's overall outcome so a published record's gate result is inspectable (seed-script rows predate the gate).
- `pipeline_run_hotels.scrape_gaps` (jsonb, nullable) records per-source scrape failures on a hotel that still completed from the other source; `pipeline_run_hotels.review_queue` (boolean, default false) flags medium-confidence publishes for the human review queue (migration `0021`).
- **One row per user** on `sessions` and `shortlists` — `UNIQUE (user_id)` (migration `0019`), enforcing the documented single rolling session (08b-3) / single working shortlist (04) invariants at the DB level.
- `public.users.email` follows `auth.users` email changes — the `handle_new_user()` trigger fires on auth-email UPDATE as well as INSERT, upserting `on conflict (id) do update set email` (migration `0019`).
- `recommendation_jobs` carries `conversation_id` (nullable text — the client-minted per-conversation correlation id, specs/14, so the worker stamps `hz.conversation_id`); `error_kind` includes `budget_mismatch` (the variant payload persists in `result`); and a **partial unique index** `(user_id, input_hash) WHERE status IN ('pending','running')` guarantees at most one in-flight job per user+input (03c AC5, no double-spend). All migration `0019`.
- Only one active pipeline run: `one_active_run` partial unique index.

## RLS plan

- Owner-only (`auth.uid() = user_id`): `family_profiles`, `trip_briefs`, `sessions`, `shortlists`. **Owner-READ-only** (service-role writes, owner SELECT): `booking_orders` (10d), `recommendation_jobs` (03c — the worker writes via service role; the client poll reads its own job).
- Read-only for authenticated users: `hotels`, `hotel_intelligence`.
- Service-role/admin only: `raw_reviews`, `raw_review_payloads`, `pipeline_runs`, `pipeline_run_hotels`, `curation_hotels`, `routestack_destinations`, `routestack_hotels`, `apify_runs`, `preview_seeds`, `raw_routestack_payloads`, `webhook_events`. (RLS enabled with **no** client policies — the service role bypasses RLS; authenticated/anon clients get zero rows.) *(list synced 2026-07-03, post-review sweep)*

## Later-phase tables (additive migrations — service-role only)

These extend the model in later phases. All are **service-role only** (RLS enabled, no client policies — mirrors `raw_reviews`) — **except `booking_orders` and `recommendation_jobs`, which add an owner-read SELECT policy** (`auth.uid() = user_id`; all writes still service-role). Columns mirror the migrations; see `docs/data-model.md` + Notion 07 for full detail. *(section extended 2026-07-03, post-review sweep)*

- **`raw_review_payloads`** (migration `0009_raw_review_payloads.sql`, Phase 6 / review pipeline) — permanently-accumulated **original untouched Apify actor dataset items**, so review mappings can be re-run without a (paid) re-scrape (`npm run pipeline:remap`). Columns: `id` (uuid PK), `hotel_id` (→ `hotels`, cascade), `pipeline_run_id` (→ `pipeline_runs`, set null), `source` (`tripadvisor` | `google`), `external_id` (nullable, actor item id for dedup), `payload` (jsonb, the untouched item), `scraped_at`. Dedup: `UNIQUE (hotel_id, source, external_id)`.
- **`routestack_destinations`** (migration `0011_routestack_id_cache.sql`, Phase 7 / booking) — caches the **stable** RouteStack destination handle per HotelZippo destination enum value, so a repeat booking skips the paid `search-destinations` call. Columns: `destination` (text PK, `check in ('Phuket','Singapore','Tokyo','Orlando','Bali')`), `rs_destination_id` (text), `rs_destination_type` (text, nullable), `lat` / `long` (double precision), `resolved_at`.
- **`routestack_hotels`** (migration `0011_routestack_id_cache.sql`, Phase 7 / booking) — maps a RouteStack hotel id ↔ our `hotels` row for **deterministic** matching (instead of fuzzy name-matching). Columns: `hotel_id` (uuid → `hotels`, cascade), `provider` (text, default `'routestack'`), `rs_hotel_id` (text), `rs_hotel_name` (text, nullable, for audit/drift), `resolved_at`. PK `(hotel_id, provider)`; index on `rs_hotel_id`. See **10c · Booking Agent & RouteStack** for the id-cache seam (`lib/booking/id-cache.ts`).
- **`apify_runs`** (migration `0012_apify_runs.sql`, Launch / curation hardening) — the **Apify run ledger**: one row per actor invocation, decoupling "the actor ran" from "we ingested it" so an expensive run is never lost, can be re-pulled free, has history, and is refreshable. Columns: `id` (uuid PK), `actor_id`, `purpose` (`curation_search` | `ta_reviews` | `google_reviews`), `scope_type` (`destination` | `hotel`), `scope_value`, `input` (jsonb), `apify_run_id` (nullable), `apify_dataset_id` (nullable, the re-pullable handle), `status` (`pending` | `running` | `succeeded` | `failed` | `ingested`), `item_count`, `ingested_at`, `error`, `cost_estimate`, `started_at`, `finished_at`. Indexes on `(purpose, scope_value, started_at desc)` + `status`. See **12h · Apify Run Ledger**.
- **`preview_seeds`** (migration `0014_preview_seeds.sql`, 12i-C / runtime preview seeding) — the per-destination **seed-once latch** for on-the-fly preview seeding from chat (a lightweight latch, NOT a run ledger — cf. `apify_runs`): `status='done'` → never re-seed at runtime (cost capped to ~5 seeds ever); `status='running'` → a concurrent request gets "in_progress", not a second paid seed. Columns: `destination` (text PK, checked against the 5-destination enum), `status` (`running` | `done` | `failed`), `hotel_count`, `error`, `started_at`, `finished_at`. **Service-role only.**
- **`raw_routestack_payloads`** (migration `0015_raw_routestack_payloads.sql`, Phase 7 / booking debug) — **append-only debug log of RouteStack API calls**, one row per call, written only when `ROUTESTACK_DEBUG_PAYLOADS=1`; request/response are **already redacted** at the app layer before insert. Columns: `id` (uuid PK), `step` (`search_destinations` | `search_hotels` | `get_hotel_details_and_rates` | `revalidate` | `get_payment_url`), `path`, `request` (jsonb, nullable), `response` (jsonb, nullable), `success` (nullable), `code` (RouteStack envelope code, nullable), `duration_ms`, `error`, `hotel_id` (RouteStack id **string**, deliberately no FK), `trace_id` (OTEL correlation), `created_at`. No dedup index (duplicates expected); indexes on `created_at` + `step`. Retention operator-managed (no TTL). **Service-role only.**
- **`booking_orders`** (migration `0016_booking_orders.sql`, 10d / booking webhooks) — **one row per booking with a lifecycle**: born "pending" at the payment-url handoff (`linked = false`, keyed by HotelZippo email + session `correlationId`), promoted to "tracked" when an inbound webhook matches it and attaches `rs_order_id` + statuses. Columns: `id` (uuid PK), `user_id` (nullable, → `users` set null), `user_email`, handoff context (`hotel_id` — RouteStack id string, no FK; `hotel_name`, `destination`, `check_in`, `check_out`, `correlation_id`, `currency`), webhook-filled tracking (`rs_order_id` **UNIQUE** — redelivered events upsert the same row; `order_status`, `payment_status`, `last_event`, `billing_email`, `price`, `linked` default false), `created_at`, `updated_at`. **Owner-READ RLS** (one SELECT policy `auth.uid() = user_id`; all writes via the service role — webhook + handoff routes).
- **`webhook_events`** (migration `0016_booking_orders.sql`, 10d) — **append-only audit log of every inbound RouteStack webhook delivery**, matched or not, holding the **REDACTED** payload (billing name/email masked) for replay/debugging. Columns: `id` (uuid PK), `source` (default `'routestack'`), `event`, `rs_order_id` (nullable), `booking_order_id` (nullable, → `booking_orders` set null), `matched` (default false), `payload` (jsonb), `received_at`. Indexes on `rs_order_id` + `event`. **Service-role only.**
- **`recommendation_jobs`** (migrations `0018_recommendation_jobs.sql` + `0019_review_fixes.sql`, 03c / async assembly) — the **async-assembly job ledger**: one row per recommendation assembly (`pending → running → succeeded | failed`), so the slow LLM call runs on the worker route's own budget and the client polls for staged progress + cards. Columns: `id` (uuid PK — the polled jobId), `user_id` (nullable, → `users` set null), `trip_brief_id` (nullable), `conversation_id` (nullable — specs/14 correlation, added 0019), `destination`, `input_hash` (reuse/idempotency key), `input` (jsonb), `status`, `stage` (`queued` | `finding_hotels` | `checking_intelligence` | `writing` | `done`), `result` (jsonb — hydrated cards on success; the error VARIANT payload on failure), `error_kind` (`no_eligible_hotels` | `budget_mismatch` | `model_failed` | `timeout` | `unknown` — `budget_mismatch` added 0019), `attempts`, `created_at` / `started_at` / `finished_at`. Indexes: reuse `(input_hash, created_at desc)`, owner `(user_id, created_at desc)`, `status`, plus the 0019 **in-flight partial unique** `(user_id, input_hash) WHERE status IN ('pending','running')`. **Owner-READ RLS** (client polls its own job; worker writes via service role). See **03c · Async Assembly**.
